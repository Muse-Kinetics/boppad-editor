## Resolved (2026-08-05/06) — web deploy shipped, two version-display bugs found and fixed

- **First-ever real web deploy ran clean** (previously dry-run-only since 2026-08-01): `npm run deploy:web` to the configured deploy target, confirmed over SSH.
- **Cloudflare edge-cached a pre-deploy copy of `bundle.js`** (`cache-control: public, max-age=604800`), so a purge was needed before the new JS was visible. `index.html` itself, by contrast, is served `cf-cache-status: DYNAMIC` (no cache-control at all) — always fresh regardless of purges. No Cloudflare API token exists in `.env`/`.env.example`, so the editor tooling cannot purge programmatically; it needs CDN dashboard access.
- **Real bug, unrelated to caching:** `apps/web/index.html` hardcoded stale placeholder version text (`editor: 1.1.1`, `firmware: 0.0.0`) that only got overwritten by JS once a physical device connected and replied — a fresh browser with no device would always show the stale hardcoded text regardless of how correct `bundle.js` was. Fixed: corrected the static placeholder text, and `app.js` now calls `updateVersionDisplay()` unconditionally on load instead of only from device-connect/online-check handlers.
- **Real bug, separate hand-maintained file:** the *online* "is a newer version published" check (`checkFirmware.js`) hits `products/boppad/firmware/currentVersion.json` — a sibling path to the editor's own deploy target, NOT the editor's bundled `firmware/currentVersion.json` — which still read `editor 1.1.1 / firmware 3.0.3` from before this migration, causing a false "new firmware available" banner against a fully up-to-date device. Fixed structurally: `apps/web/scripts/deploy-build.js` now generates and uploads this file itself on every deploy from the same sources of truth as the rest of the release, instead of relying on a hand-edited copy.

## Not Current Blockers (resolved during migration)

- **Firmware flash — RESOLVED, hardware-validated 2026-08-03.** The chunked local-first update now flashes a physical BopPad end-to-end (enter bootloader → 566 chunks with between-chunk identity handshake → reboot → verify), with a K-Board-style progress dialog. **A real Web MIDI bug was found and fixed in the process:** BopPad uses a SEPARATE `BopPad Bootloader` port (unlike K-Board, which stays on one port), and the freshly-enumerated bootloader **input** port must be explicitly `.open()`ed with a persistent `onmidimessage` handler — an `addEventListener` on a just-appeared port silently delivered nothing, so the first between-chunk identity reply was never received and the transfer aborted at chunk 1. Fixed in `firmwareUpdater.js` (open both bootloader ports + `onmidimessage` + `ackTimeoutMs:5000` matching K-Board). Recovery path (`SendSysEx --fw-update BopPad`) was built and proven (it cleanly re-flashed a device left in bootloader by the pre-fix attempt). Bootloader-state detection confirmed identical to K-Board/sendsysex (PID-MSB byte, `data[9]`).

- **electron-builder 24.x mac build failure:** resolved by pinning `electron-builder ^23.0.3` — 24.13.3's `7zip-bin` throws `chmod 7za` ENOENT. See "electron-builder must stay on ^23.0.3" in decisions.md.
- **Dropbox dehydrates `node_modules`:** the repo lives in Dropbox, which turns installed modules into online-only placeholders → `Cannot find module 'dotenv'`, missing `7za`, etc. Resolution: **pause Dropbox, then clean `rm -rf node_modules && npm install`** so the fresh tree stays materialized. Recurs whenever Dropbox re-dehydrates; re-apply as needed.
- **Node version trap:** the machine's nvm default is **v13**, which fails on modern JS syntax and lacks `node --test`. Use Node 24 explicitly — `~/.nvm/versions/node/v24.15.0/bin` on `PATH`, or `nvm use` (reads root `.nvmrc` = 24). Not a blocker once selected; noted because a non-interactive shell silently runs v13.
- **contextIsolation blanked the renderer:** attempting `contextIsolation: true` / `nodeIntegration: false` painted the jQuery app blank with no JS error. Resolution: reverted to `nodeIntegration: true` / `require('electron')`; hardening deferred to a later DevTools session. See decisions.md.
- **electron-builder `install-app-deps` postinstall failure** (`Cannot compute electron version`): BopPad has no native modules, so the no-op postinstall was removed.
